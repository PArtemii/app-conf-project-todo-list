# ADR 002: Инструменты для работы с кодом бэкенда

**Статус:** Принято  
**Дата:** 22.10.2026  
**Команда:**

**Проект:** ИИ-Ассистент к To-Do List

## Контекст
ИИ-агенту необходимы инструменты для поиска по кодовой базе, чтения исходных файлов и статического анализа бэкенда. Главные риски безопасности — уязвимость Excessive Agency (избыточные права ИИ) из OWASP Top 10, риск Prompt Injection через читаемый код бэкенда и риск перегрузки контекста модели лавиной данных.

## Рассмотренные варианты
1. Использование универсального системного инструмента выполнения команд типа `shell=True`. (Отклонено из-за критической уязвимости: модель может выполнить деструктивные команды).
2. Раздельные детерминированные инструменты с жесткой валидацией путей через `Path.resolve()` и `is_relative_to()`. (Выбрано).
3. Навязывание бэкенду конфигурации линтера из папки помощника. (Отклонено, так как ИИ-слой не должен навязывать свои правила стороннему коду).

## Решение
Разработаны три изолированных инструмента чтения (`read_file`), поиска (`search_codebase`) и анализа (`run_linter`).
Внедрена строгая граница доступа: путь принудительно нормализуется, блокируются любые попытки выйти за границы `AI_REPO_ROOT` или прочитать файлы из списков `AI_DENY_GLOBS`. Любые сбои утилиты `ruff` (код возврата 2 и выше) перехватываются и возвращаются агенту как `status: error`, запрещая модели выводить ложное «замечаний нет».

## Последствия
* **Плюсы:** Полная изоляция бэкенда. ИИ работает исключительно в режиме «только чтение». Система гарантированно защищена от чтения файлов окружения `.env` и системных папок `venv`.
* **Минусы:** Написание жестких ручных проверок диапазонов строк и типов параметров.

## Наблюдения из трассы
* `run-p2-01.log`: Агент успешно использовал связку `search_codebase` (для поиска функции `health_check`) и `read_file` для демонстрации её исходного кода из `main.py`.
* `run-p2-02.log`: В сценарии с битым конфигурационным файлом `ruff.toml` инструмент вернул явную ошибку. Агент корректно распознал сбой, не утаил ошибку от пользователя и вывел вердикт «Результат проверки неизвестен».

## Когда пересмотреть
При необходимости внедрения агентов-кодеров с правами на запись или переходе на внешние облачные API-инструменты анализа.
