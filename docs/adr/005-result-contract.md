# ADR 005: Контракт результата помощника

**Статус:** Принято
**Дата:** 20.11.2026  
**Команда:** 404

## Контекст

После практики 4 Crew возвращает текстовый итог. Из него разработчик может прочитать, какой тест Кодер считает записанным, но программа не может надёжно сверить путь к файлу и эндпоинт без разбора свободного текста.

В практике 5 проверяем `GET /version`. OpenAPI подтверждает наличие метода и пути, а значения `version="0.2.0"` и `team="404"` берём из кода бэкенда. Форма результата должна позволить проверить, что Crew указала существующую операцию API и действительно записала файл в текущем запуске.

## Рассмотренные варианты

1. Сохранить текстовый `expected_output` практики 4. Для проверки имени эндпоинта и файла пришлось бы разбирать произвольные формулировки.
2. Описать итог последней задачи с помощью Pydantic-модели `CrewResult`. Передачу между Исследователем и Кодером оставить текстовой.
3. Добавить отдельные структурированные модели для итога Crew и передачи между агентами. Это увеличит объём изменений и число контрактов для проверки.

## Решение

Выбираем вариант 2. Последняя задача Crew будет возвращать `CrewResult` через `output_pydantic`. Используем обязательные поля из `docs/result-contract.md` без дополнительных полей.

Исследователь получает сводку через `get_openapi_schema`. Tool без аргументов читает только `GET /openapi.json` по адресу из `AI_BACKEND_URL`. Код итоговой проверки использует полную OpenAPI-схему, поскольку сводка для модели может быть сокращена.

Pydantic проверяет обязательные поля и их формат. После этого приложение сверяет пару метод + путь с полной схемой, проверяет существование и свежесть файла и учитывает статус поиска при проверке записи. При отказе разработчик получает сообщение и код выхода `1`.

Разработчик сверяет статус и поля ответа с кодом бэкенда, проверяет фактический вывод Ruff и самостоятельно запускает `pytest`.

## Последствия

Структурированный результат позволяет автоматически выявить выдуманный эндпоинт, отсутствующий файл и файл, оставшийся от предыдущего запуска. Сообщения о нарушениях можно приложить к Pull Request вместе с трассой.

Модель должна заполнить больше полей, поэтому возможны отказы формата и дополнительный вызов конвертера. Для живого прогона нужен доступный источник OpenAPI. Корректность проверок внутри сгенерированного теста подтверждается по коду и результатам ручного запуска.
Для сравнения используется замер практики 4 — 9 вызовов LLM, 3,0 минуты.
## Результаты запуска

| Прогон | Исход | Трасса |
|---|---|---|
| Первый | Процесс завершился с кодом `-1` после ошибки кодировки `charmap`. Итоговый объект не получен. | `ai/traces/run-p5-01.log` |
| Повторный, с UTF‑8 | Crew вернула структурированный результат со статусом `found` и путём `generated/test_version.py`. | `ai/traces/run-p5-01-2.log` |

В повторном прогоне использовалась локальная модель `qwen3:4b-instruct`.
Схема получена с Docker-стенда по адресу `http://127.0.0.1:8000/openapi.json`.
Замер повторного прогона — 10 вызовов LLM и 4,5 минуты.
В практике 4 было 9 вызовов и 3,0 минуты.

Crew указала `GET /version`, ожидаемый статус `200` и поля
`version="0.2.0"` и `team="404"`. Эти значения совпадают с реализацией
в `main.py`. Ручной запуск `python -m pytest generated -q` завершился
с итогом `2 passed, 1 warning in 0.84s`. Предупреждение о deprecated
`BlockingPortal` выдала зависимость Starlette.

Ruff обнаружил `I001` в `generated/test_version.py:1:1`. Это совпадает
с полем `linter_result: "замечаний осталось"`. В поле `note` Crew
ошибочно указала, что `I001` исправлен. Файл сохранён в состоянии,
в котором его сгенерировала Crew.
## Связь с ADR 004 помощника

Сохраняем последовательность Исследователь → Кодер из [ADR 004](adr-004-orchestration-pattern.md). Исследователь получает дополнительный источник данных в виде OpenAPI. Кодер по-прежнему записывает отдельный Python-файл, а его итог принимает форму `CrewResult`.

## Когда пересмотреть

Пересмотреть решение, если у `GET /version` появится `response_model` и OpenAPI начнёт описывать структуру тела, если потребуется проверять больше операций или если первый прогон покажет, что ошибки возникают уже при передаче данных от Исследователя к Кодеру.
