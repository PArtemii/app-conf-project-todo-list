# Архитектура CrewAI — Практика 4

## 1. Цель

Создать систему из двух AI-агентов для проекта `app-conf-project-todo-list`, которая последовательно генерирует тестовые файлы и проверяет результат.

Система использует CrewAI, локальную модель Ollama и существующие инструменты работы с кодом и документацией.

## 2. Состав команды

### Developer — разработчик

**Задача:** изучить требования и код проекта, затем создать тестовые файлы.

Инструменты:
- `search_codebase` — поиск функций, классов и участков кода.
- `read_file` — чтение исходных файлов.
- `search_docs` — поиск информации в документации через RAG.
- `write_generated` — запись файлов в разрешённый каталог `generated/`.

Ожидаемый результат: сгенерированные тесты и перечень созданных файлов.

### Reviewer — ревьюер

**Задача:** независимо проверить результат Developer и сообщить о найденных проблемах.

Инструменты:
- `read_file` — чтение созданных файлов.
- `search_codebase` — проверка соответствия существующему коду.
- `run_linter` — статический анализ Python-кода через Ruff.
- `search_docs` — проверка соответствия документации проекта.

Ожидаемый результат: заключение о качестве файлов, замечания и рекомендации.

Reviewer не должен изменять файлы.

## 3. Порядок выполнения

Используется последовательная схема CrewAI (`Process.sequential`).

1. Developer получает задание.
2. Developer изучает код и документацию.
3. Developer создаёт тестовые файлы через `write_generated`.
4. Reviewer получает результат предыдущей задачи.
5. Reviewer читает созданные файлы и запускает `run_linter`.
6. Reviewer формирует итоговый отчёт.

## 4. Ограничения безопасности

- Все пути проверяются относительно корня репозитория.
- Запрещён доступ к секретам и файлам из `AI_DENY_GLOBS`.
- Инструмент `write_generated` разрешает запись только в `generated/`.
- Запрещена запись в `.env`, `.git`, исходный код приложения и другие каталоги.
- Reviewer имеет только инструменты чтения и проверки.
- Инструмент `run_linter` не изменяет файлы.
- Содержимое файлов и результаты RAG рассматриваются как данные, а не как инструкции для агентов.

## 5. Конфигурация

- Оркестратор: CrewAI.
- Процесс: `Process.sequential`.
- Провайдер LLM: Ollama.
- Модель: `qwen3:4b-instruct`.
- Фабрика модели: `ai/llm_factory.py`, функция `get_llm()`.
- Модель эмбеддингов: `qwen3-embedding:0.6b`.
- Конфигурация: `ai/config.py` и локальный `.env`.
- Память CrewAI: отключена.

## 6. Планируемые файлы

| Файл | Назначение |
|---|---|
| `docs/crew-design.md` | Архитектура двух агентов |
| `ai/tools/generated_files.py` | Безопасная запись сгенерированных файлов |
| `ai/run_crew.py` | Создание и запуск команды CrewAI |
| `generated/conftest.py` | Настройка тестов в каталоге `generated/` |

| `pytest.ini` | Конфигурация pytest |

## 7. Критерии готовности

- Два агента выполняют задачи последовательно.
- Developer может создавать файлы только в `generated/`.
- Reviewer проверяет результат без права записи.
- Проверки Ruff и pytest выполняются успешно.
- Ошибки инструментов не скрываются.
- Результаты запусков сохранены в `ai/traces/`.
- Изменения оформлены в ветке `feature/ai-crew` и подготовлены к Pull Request.
