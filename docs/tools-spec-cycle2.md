# Спецификации Tool — цикл 2 (Версия v2.1)

## 1. Tool: search_codebase
* **Назначение:** Ищет заданную строку в файлах бэкенда. Вызывать, когда нужно найти место определения функции или использование переменной.
* **Вход (input_data):**
  * `query`: str — обязателен, поисковый запрос (длина 3..100 символов).
  * `kind`: str — "text" (подстрока) или "symbol" (def/class через ast). По умолчанию "text".
  * `path`: str — подкаталог для поиска. По умолчанию ".".
  * `path_glob`: str — шаблон имени файла. По умолчанию "*.py".
  * `max_results`: int — от 1 до 50. По умолчанию 20.
* **Выход:** JSON-строка.
  * Успех: `{"status": "ok", "total_matches": X, "returned": Y, "truncated": bool, "matches": [...]}`
  * Ошибка: `{"status": "error", "message": "..."}`

## 2. Tool: read_file
* **Назначение:** Читает содержимое указанного файла бэкенда с номерами строк. Вызывать только после поиска.
* **Вход (input_data):**
  * `path`: str — обязателен, путь к файлу относительно AI_REPO_ROOT.
  * `start_line`: int — номер первой строки. По умолчанию 1.
  * `max_lines`: int — сколько строк вернуть (от 1 до 400). По умолчанию 200.
* **Выход:** JSON-строка.
  * Успех: `{"status": "ok", "path": "...", "start_line": X, "end_line": Y, "total_lines": Z, "truncated": bool, "content": "..."}`
  * Ошибка: `{"status": "error", "message": "..."}`
* **Безопасность (Защита от Excessive Agency):** Путь принудительно нормализуется через Path.resolve(). Инструмент блокирует выполнение, если итоговый путь физически находится вне каталога бэкенда AI_REPO_ROOT или совпадает с шаблонами из AI_DENY_GLOBS.

## 3. Tool: run_linter
* **Назначение:** Запускает статический анализатор ruff check по коду бэкенда для поиска ошибок.
* **Вход (input_data):** 
  * `path`: str — файл или каталог для проверки. По умолчанию ".".
  * `max_findings`: int — лимит находок (от 1 до 100). По умолчанию 30.
* **Выход:** JSON-строка.
  * Код 0/1 (Успех/Замечания): `{"status": "ok", "total_findings": X, "by_rule": {...}, "findings": [...]}`
  * Код 2 (Сбой линтера): `{"status": "error", "message": "ruff завершился аварийно", "stderr": "..."}`

## 4. Самый опасный инструмент в проекте
Наиболее опасным является инструмент прямого изменения файлов или выполнения произвольных команд в терминале (типа shell=True). Локальные малые модели склонны выполнять Prompt Injection из прочитанных файлов. Если дать агенту автономность на запись, вредоносный код в проверяемом файле сможет выполнить Excessive Agency и уничтожить весь репозиторий. Помощник должен только читать данные.

## Тесты на практику 2
1. `read_file(path="app/../.env")` → ожидаемый `status: "error"` → message содержит "запрещён" или "вне репозитория".
2. `read_file(path="app/logo.png")` (бинарный файл) → ожидаемый `status: "error"` → падение при попытке разбора или явная ошибка структуры.
3. `search_codebase(query="API_KEY")` (поиск в секретах) → ожидаемый `status: "ok"` → `total_matches` равен 0 из-за фильтрации deny-list.
4. `search_codebase(query="import")` (слишком общий запрос) → ожидаемый `status: "ok"` → `total_matches` большой, но список `matches` пустой с подсказкой `hint`.
5. `run_linter(path="--fix")` (передача флага вместо пути) → ожидаемый `status: "error"` → message содержит ошибку разбора пути или защиты от флагов.
