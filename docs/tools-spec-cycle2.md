# Спецификации Tool — цикл 2 (Версия v2)

## 1. Tool: search_codebase
* **Назначение:** Ищет заданную строку в файлах бэкенда. Вызывать, когда нужно найти место определения функции или использование переменной.
* **Вход (input_data):**
  * `query`: str — обязателен, поисковый запрос (длина 3..50 символов).
* **Выход:** JSON-строка.
  * Успех: `{"status": "ok", "matches": [{"file": "main.py", "line": 12, "text": "..."}]}` (лимит вывода — не более 20 совпадений для token efficiency).
  * Ошибка: `{"status": "error", "message": "..."}`

## 2. Tool: read_file
* **Назначение:** Читает содержимое указанного файла бэкенда. Вызывать только после поиска.
* **Вход (input_data):**
  * `file_path`: str — обязателен, путь к файлу относительно AI_REPO_ROOT.
* **Выход:** JSON-строка.
  * Успех: `{"status": "ok", "content": "..."}`
  * Ошибка: `{"status": "error", "message": "..."}`
* **Безопасность (Защита от Excessive Agency):** Путь принудительно нормализуется через Path.resolve(). Инструмент блокирует выполнение, если итоговый путь физически находится вне каталога бэкенда AI_REPO_ROOT. Прямой доступ к .env и venv закрыт кодом.

## 3. Tool: run_linter
* **Назначение:** Запускает статический анализатор ruff check по коду бэкенда для поиска ошибок.
* **Вход (input_data):** Нет параметров (запускается по всему корню бэкенда из конфига).
* **Выход:** JSON-строка.
  * Код 0 (Чисто): `{"status": "ok", "message": "Ошибок не найдено"}`
  * Код 1 (Найдены ошибки): `{"status": "warning", "errors": [...]}` (структурированный список ошибок без лишнего шума)
  * Код 2 (Сбой линтера): `{"status": "error", "message": "Сбой конфигурации ruff"}`

## 4. Самый опасный инструмент в проекте
Наиболее опасным является инструмент прямого изменения файлов или выполнения произвольных команд в терминале (типа shell=True). Локальные малые модели склонны выполнять Prompt Injection из прочитанных файлов. Если дать агенту автономность на запись, вредоносный код в проверяемом файле сможет выполнить Excessive Agency и уничтожить весь репозиторий. Помощник должен только читать данные.

## Тесты на практику 2
1. `read_file(file_path="../.env")` → ожидаемый `status: "error"` → message содержит "Доступ запрещен: выход за пределы репозитория".
2. `read_file(file_path="venv/lib/package.py")` → ожидаемый `status: "error"` → message содержит "Доступ к системным каталогам окружения закрыт".
3. `search_codebase(query="ab")` → ожидаемый `status: "error"` → message содержит "Запрос слишком короткий, минимум 3 символа".
4. `search_codebase(query="A"*100)` → ожидаемый `status: "error"` → message содержит "Превышена максимальная длина запроса".
5. `run_linter()` при сломанном файле ruff.toml → ожидаемый `status: "error"` → message содержит "Сбой конфигурации ruff".
